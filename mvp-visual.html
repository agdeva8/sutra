Core Insight
Zero-friction capture works. Silent rescheduling kills trust.
Will it work? Too early to know.
Should you build it? Yes — but only after the dogfood gate.

The evidence says this category dies from:

1. Daily upkeep effort — solved by Scratch's zero-friction capture

2. Noisy auto-rescheduling — solved by structural downgrade (diff check before commit)

3. Forgotten context — solved by memory and provenance tracing

The risk: All three solutions exist on paper. None are proven in production.

The gate before building:

✓ Run 14 days of plain note-taking with no tool. If you capture ≥12/14 days, the loop is wanted.

✓ Show ≥8/10 correct filing from a plain LLM triage. If not, the interpreter needs work before you code it.

✗ Do NOT build the full MVP first. The sunk cost will bias your judgment.

The verdict: Build the core (text capture + interpreter + diff check + provenance + undo). Ship it to yourself first. The architecture is sound. The execution risk is behavioral, not technical.
